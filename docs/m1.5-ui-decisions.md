# M1.5-UI — backend picker, OTP login, auth routing (locked decisions)

**Status:** Design locked 2026-11-03 (owner call). Code is **device-gated** — the
pure-Dart seam (`BackendConfig`, `OtpLogin`) already landed on this branch; what
remains is Flutter UI + an `AppState` wiring that needs a device/simulator to build
and verify.

**Companion to:** `bether-backend/docs/multi-backend-client.md` §7b (same decisions,
backend view). This file is the app-side task spec.

---

## Decisions

### 1. Backend entry — QR scan **and** manual URL, both
- Two ways to add a backend: **scan a QR** carrying a URL, or **type a URL**.
- Both resolve the same way: `BackendConfig.fromDescriptor(url)` → `GET
  {url}/.well-known/gather-backend.json` → build the config.
- **No inline-profile QR** — descriptor URL only.
- The selected backend(s) **persist on the device** (keychain / prefs store), keyed
  by profile id. Credentials are per profile (already the design).

### 2. Switching — settings switcher, any time + first-run walkthrough
- A **settings** screen adds / switches / removes backends at any time.
- **First launch** shows a short **walkthrough** introducing "add a backend."
- Needs the `BackendProfile` store + "active profile" state in `AppState`.

### 3. Default on fresh install — none forced
- No Gather-first, no bether-first. A clean install has **no active backend**; the
  user scans or types one to begin.
- The built-in Gather profile still exists as a pickable option, just not
  auto-selected.

### 4. Auth is per backend — bether is **not** locked to OTP
- **Gather** → existing screens/flow (Firebase pairing / web login). Unchanged, no
  alternative.
- **bether-style backends** → may offer **email + password**, **Google**, or
  **Apple** sign-in — **no embedded webview (no webkit)**. OTP (`OtpLogin`) is the
  one producer already built.
- Which strategies a backend supports comes from the descriptor's
  `auth.strategies`; the app renders only those.

### 5. Login routing — selected backend decides the screen
- Pick a backend → see that backend's login. **No combined multi-strategy screen.**

## Task breakdown (app side)

| Task | Gate |
|---|---|
| `BackendProfile` store (keychain, per id) + active-profile in `AppState` | device |
| First-run walkthrough + settings backend picker (QR scan already exists in `lib/ui/pair_screen.dart` / `settings_screen.dart`; point "add backend" → `fromDescriptor`) | device |
| OTP login screen (email → code) calling `OtpLogin`, store as active profile's `GatherCredentials` | device |
| De-const remaining hosts onto the active `BackendConfig` (`GatherAuth`, `DirectCollector(socketUrl:)`, SFU/asset hosts) | device |
| Login routing on `descriptor.auth.strategies` | device |
| Google / Apple native sign-in screens | OAuth secret (Apple dev acct, Google cloud project) + native SDK + device |

## Backend dependency

Email + password / Google / Apple need **new backend auth** that bether does not
yet ship (today: email-OTP only):
- `email + password` → `/auth/password` + password-hash column — backend-only,
  buildable without a device (see bether-backend doc §7b.4).
- `Google` / `Apple` → OAuth client IDs = secret/human gate.

The existing OTP path is fully wired end-to-end on the backend; the OTP login
screen can land as soon as there's a device, with no further backend work.
